# Cross-harness evidence handoff — local learned procedure

> HCA10 — Sanitized historical source excerpts. Date basis: undated local skill; snapshot chronology not inferred. Status: owned learned workflow excerpts; tool availability must be probed.
> Historical gates, model choices, thresholds and provider preferences are optional context, not current requirements. No runtime execution is asserted.

Selected procedure retains raw-versus-summary handoff, relevance grades and wrapper-failure lessons. Machine-specific scratch paths and repair commands are omitted. The recommendation to choose a winner does not justify a choice when evidence is insufficient.

---

## 1. Establish a capability map before dispatch

Record each required source as `LIVE`, `DEGRADED`, `BLOCKED`, or `NOT USED` for the current harness. Check the actual Codex MCP inventory instead of assuming Hermes tools are inherited by Codex.

Build a `WANT × SOURCE` matrix for:

- local canon and ratification;
- recovered Drive/Notion/source packages;
- live storefront and platform state;
- competitor pages and customer evidence;
- ads/intelligence sources;
- social/recent research;
- analytics and attribution;
- independent verification.

Use every relevant live source, not every tool indiscriminately. A broad tool call that returns noisy entities is discovery evidence, not final positioning evidence.

## 2. Collect unavailable-to-Codex evidence in Hermes

When Hermes has an intelligence connector or another connector absent from Codex:

1. Run the live reads in Hermes.
2. Preserve raw responses unchanged.
3. Build a compact summary containing exact advertiser/entity counts, repeated messages, dates, URLs, relevance grades, and degraded states.
4. Grade entity relevance:
   - `A`: exact brand/domain or first-party source;
   - `B`: relevant independent review/source;
   - `C`: adjacent, noisy, model-generated, or ambiguous.
5. Give Codex both the raw files and the summary. Require it to inspect raw evidence rather than trust generated “opportunity” boilerplate.

## 3. Separate evidence from positioning language

Require four explicit states in the research report:

- `OBSERVED`: directly present in a source/live dataset;
- `CORROBORATED`: supported by at least two independent source groups;
- `INFERRED`: analytical conclusion;
- `TEST CANDIDATE`: bold language proposed for behavioral validation.

Aggressive positioning is encouraged. Inflated certainty is not. The report must choose one winner, score alternatives, state the strongest counterargument, and identify which current canonical line becomes the control rather than silently overriding canon.

A strong positioning deliverable includes:

- familiar market category;
- best-fit customer and anti-audience;
- JTBD and struggling moment;
- occupied-language map;
- white-space mechanism, not just a new adjective;
- final positioning statement, brand line, homepage copy, hooks, and visual system;
- family/collection roles;
- SEO/AEO/CRO implications;
- primary research and behavioral test plan;
- exact reconciliation against existing ratification.

## 4. Treat wrapper success and data success separately

A tool can return HTTP 200 while still returning no usable evidence. Detect and classify:

- typed-wrapper argument drift versus native schema (`brand` vs `competitor`, `keyword` vs `niche`);
- all-null transcript/analysis payloads;
- `profile: null` marked as live;
- same-name competitor candidates without domain confidence;
- empty or irrelevant broad keyword results;
- provider timeouts and account gates.

Probe the free native tool inventory first. If a typed wrapper rejects a required field, retry through the generic native relay using the actual native schema. This proves the upstream path and isolates the wrapper defect. Preserve the generic raw relay exactly; typed surfaces may add bounded sidecar metadata but must not mutate upstream data.

Never convert an upstream gate into fabricated success. Never turn an empty payload into an absence claim about the market.
