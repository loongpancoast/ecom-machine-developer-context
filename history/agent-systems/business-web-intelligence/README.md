## Adaptation and integration limits

- Identity references were neutralized. Private dependency lists and repository-specific commands were replaced with explicit adaptation notes. The surviving instructions, tool declarations, evidence requirements, and output filenames retain their historical structure. These are sanitized originals, not verbatim originals.
- `workspace/` locations are illustrative application-relative runtime destinations, not package links or original source locations. Other backticked lifecycle filenames are request-relative runtime artifacts, not bundled documents.
- Supply guardrails, an evidence schema, routing policy, and workflow contracts. Dashboard generation, scheduling, canonical-index synchronization, and search adapters are not included or tested. `Read`, `Write`, `Edit`, `Grep`, `Glob`, and `Bash` are historical harness tool labels, not executable integrations here.
- The router retains a Social / Creative destination to preserve its routing behavior; that specialist is intentionally not included in this selection. No image/video definition, copywriting module, or unreviewed sales/legal/blog prompt body is included.
- Historical approval-heavy rules, provider ordering, cost caps, Stage-0 language, and Markdown/index architecture are optional context, not current requirements. Evaluate live provider functionality and access rules separately.
- Evidence normalization does not itself authorize canonical promotion. Index/search projections and dashboards do not become independent authorities. Output status is not proof of execution.
